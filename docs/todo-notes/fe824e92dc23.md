## 1. "env printf under a read ceiling succeeds" holds at the harness seam, not through the sibling analyzer — yet

Gate line: *"a node running printf of its env under a read ceiling succeeds
and its stdout lands in the typed port."*

The harness half is implemented and tested: typed inputs are composed as
`export YCODE_IN_<PORT>='…'` lines plus one `printf '%s' '<json>' | { … }`
stdin feeder, the composed script is exactly what preflight analyzes and what
the digest-bound authorization covers, and stdout lands in the declared out
port (`TestBashyRunProjectsEnvAndStdinIntoTypedPort`, which runs the composed
script through a real shell behind the `BashyBoundary` seam).

What cannot pass end-to-end today: the sibling
`bashy/pkg/harnessrunner` intent compiler treats **any variable expansion in
command arguments** as unprovable (`staticWord` → `dynamicCommand` →
`Intent.Complete=false`), and incomplete preflight is force-denied everywhere
(ycode `decide()` and the stage itself both fail closed, and
`Executor.run` refuses to execute an incomplete intent). So
`printf "%s" "$YCODE_IN_X"` — any consumer of the env mechanism — is denied
with the real executor no matter which policy is compiled. The composed
wrapper itself is analyzer-neutral (the `export` lines parse as declarations
the walker ignores; the static `printf` feeder is a pure builtin), so the
moment the analyzer gains argument refinement for pure builtins the whole
path opens up with no ycode change.

Pinned by `TestBashyRunEnvExpansionIsIncompleteEvidenceUnderRealBoundary`
(expected to flip when a bashy-side refiner lands; delete that test then).
The fix belongs in `bashy/pkg/harnessrunner` (a refiner proving that variable
arguments to effect-`pure` builtins add no governed effect), which is outside
this story's repo scope.

## 2. Files touched beyond the story list (why)

- `internal/harness/bashy/executor.go` (`reportFor`): atlas `pure` facts are
  kept in the typed `EffectFacts` review evidence but no longer enter the
  compact `Effects`/`Paths` policy indexes. `pure` asserts the *absence* of a
  governed effect and is outside the compiled effect vocabulary
  (`knownEffect`), so indexing it made every pure builtin unmatchable by any
  allow rule — the canonical workspace policy could not even allow
  `printf 'x'`, which the example `workspace-probe` node (and any real turn)

## Notes for Y2 (bashy-kb provider)

- The out port targets a root state slot; slot type `string` receives raw
  stdout, any other type requires stdout to parse as one JSON document.
- `bashy.run` node ids are globally unique across pipelines (compile error
  otherwise); the id keys events and Bashy idempotency.
- Node `with.effects` must sit within `spec.bashy.execution.effectsCeiling`
  (checked at turn construction) and preflight evidence must sit within the
  node ceiling (checked per call, before policy.evaluate).
- Policy is the owning agent's `policyRef`; anything but `allow` fails the
  node — there is no HITL detour for harness-authored calls.
