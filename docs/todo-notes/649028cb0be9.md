# Story 649028cb0be9 (sprint 163 Y2, bashy-kb provider) — residue notes

Everything in the story is implemented: `memories.<name>.provider: bashy-kb`
is the only compiled provider (memex rejected at compile), recall is a
`bashy.run` node running `bashy kb context --json` with the YAML memory
policy compiled into flags, persist is a `bashy.run` node running `bashy kb
note add --candidate --ring agent --episode <session>` once per turn, the
prompt port renamed `memory` -> `knowledge` with `ring`/`form`/`ref`
provenance in `prompt.assembled`, `pkg/ycode/harness.go` no longer calls
`memex.Open` (no memex directory is created under the control root on Load;
pinned by a test), `stages/memory` keeps Measure/Compact only, and the frozen
envelope is carried byte-identical in
`internal/harness/stages/memory/testdata/kb-context-envelope.json`.
`pkg/memex` stays in-tree untouched, per the story, until C8's migration has
run on the live stores.

## 1. Literal substitution, not `$YCODE_IN_<PORT>` (per docs/todo-notes/fe824e92dc23.md)

The sibling `bashy/pkg/harnessrunner` analyzer marks any variable expansion
in a command argument unprovable, and incomplete preflight is force-denied,
so `bashy kb context --for "$YCODE_IN_TASK"` can never execute. The provider
therefore composes kb commands through a `{{...}}` script template:

- `{{memory.rings}}`, `{{memory.forms}}`, `{{memory.budget}}` (=
  `recall.maxTokens`), `{{memory.k}}` (= `recall.maxItems`) are resolved at
  **compile** time from the node's `with.memoryRef` — YAML stays the sole
  policy source and the flags cannot drift from the memory resource.
- `{{<port>}}` and the reserved `{{session}}` are resolved at **stage** time
  (`internal/harness/turn/template.go`) as single-quoted shell literals,
  before preflight, so the digest-bound authorization covers the fully
  composed script. Unknown placeholders are compile errors; a non-scalar port
  in a template fails the stage closed. `session` is now a reserved bashy.run
  input-port name.

## 2. The kb commands are still denied under the real embedded executor

The analyzer completes only pure builtins today ("only a pure applet is
effect-complete"), and the pinned siblings predate B1's kb atlas rows, so
`bashy kb context ...` — even fully literal — is incomplete evidence and is
denied under the real boundary. The canonical fixture handles this **in
YAML**: the `knowledge` and `remember` turn nodes are `fallback` forms whose
second attempt is a pure-printf degradation (`empty-knowledge` emits an
honest abstained envelope `{"abstained":true,"blocks":[]}`; `skip-persist`
emits a marker string). The denial stays on the event log
(`bashy.run.completed` outcome `denied`), and the moment the siblings learn
`bashy kb` (B1 atlas rows + an argument refiner), attempt one starts
succeeding with no ycode change. The stub boundary in tests returns the
frozen golden envelope for `bashy kb context`, and the knowledge-port test
(`internal/harness/turn/knowledge_test.go`) asserts it appears in
`prompt.assembled` with block provenance.

## 3. `write.everyTurns` accepts only 1

The story gates persist "in YAML by write.everyTurns". The persist node runs
once per compiled turn and no session turn counter exists yet (Y3 territory),
so no mechanism can honor `everyTurns: N > 1`. Instead of silently writing
every turn anyway, the compiler rejects any value other than 1
(`internal/harness/spec/memories.go`). When a turn counter lands, the
restriction can be lifted together with a real gate.

## 4. `history` port awaits Y3

The story's target order is `prompt.assemble [context, knowledge, history,
input]`. Y3 (session.load / session.commit) had not landed on this branch, so
the example assembles `[context, knowledge, input]` and the turn tail is
`remember || output` instead of `... || session.commit`. Adding the history
port belongs to Y3's `session.load` output; the assemble contract change here
was kept additive (memory -> knowledge rename only) to avoid colliding with
that lane in the shared hub files.
