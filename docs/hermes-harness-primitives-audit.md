# Hermes Agent harness primitives audit

Status: Sprint 106 story `bdc739ead925` evidence map  
Audited prior art: `priorart/hermes-agent` at `a2b5d4d4900e40823e530caaa0c610f2a2f84e36`  
Scope: read-only extraction for the YAML-native Bashy harness; this is not a Hermes compatibility layer.

## Decision

Hermes provides useful contracts for normalized provider messages, deterministic call identity, ordered bounded execution, compression fencing, durable delegation, and lifecycle results. The harness should reuse those contracts while removing tool-name rules, process-local state, and product branches. YAML owns the graph and policy, neutral Go owns deterministic durable mechanisms, and Bashy is the sole model-facing tool and sole command executor.

Ownership labels:

- **B — Bashy:** command parsing/preflight, isolation, credentials, process execution, cancellation, and typed process outcomes.
- **Y — YAML:** graph topology, admission, concurrency, dedupe policy, approval routes, safe points, compaction, branch/delegate budgets, and lifecycle transitions.
- **G — neutral Go:** validation, normalization, expression evaluation, append-only events, typed state, CAS/leases, queues/outboxes, and adapter interfaces. G may enforce a declared YAML rule; it may not invent one.

## Required graph contract

```text
typed input/steer -> admission / policy.evaluate -> load typed state
  -> render context by digest -> model.invoke -> normalize response/call IDs
  -> dedupe policy -> reserve budgets/resources -> deterministic execution plan
  -> bashy.preflight -> policy.evaluate -> [approval.wait] -> bashy.execute
  -> append settlement/checkpoint -> loop or typed outcome route
  -> [branch | compact/successor | agent.invoke/join] -> sink outbox
```

Every model request, Bashy command, branch, compaction, child launch, hook, and delivery is effect-safe under replay: intent is durable before I/O, settlement is typed after I/O, and retry retains one idempotency key. Loop-carried state is schema-typed and revisioned.

## Priority changes to Sprint 106

1. **P0 — Bind every effect and approval.** Require Bashy intent digest, config/state revisions, run/node/attempt, lifecycle generation, expiry, and durable allow/deny/approval receipt; default unknown to deny.
2. **P0 — Eliminate hidden execution.** The model sees only Bashy; skill expansion, hooks, compression helpers, and child work cannot invoke direct shell or native product tools.
3. **P0 — Make concurrency replay-safe.** YAML declares claims/caps; G uses durable queues, leases, CAS, ordered settlements, cancellation, and ambiguous-effect reconciliation. Never detach an effectful worker and call it terminal.
4. **P1 — Type normalization and control input.** Preserve immutable raw responses, deterministic normalized call IDs and repair receipts, explicit duplicate policy, and durable typed steering rather than prompt-text markers.
5. **P1 — Unify branch/compaction/child lifecycle.** Use typed lineage edges, source watermarks, atomic checkpoints, resource budgets, joins, outboxes, and restart reconciliation without product runtime modes.

## Explicit non-extractions

- No Hermes/provider/platform/tool-name branch, model roster, parallel-safe allowlist, danger regex, retry count, depth, or budget in the Go interpreter.
- No direct `bash -c`, Python subprocess, native tool implementation, or alternate model-callable tool beside Bashy.
- No ambient environment/session flag as authority; no fail-open approval; no transcript phrase as consent; no reuse after intent mutation.
- No process-local-only steering, approval queue, lifecycle registry, worker thread, object-identity marker, or PID identity as durable truth.
- No argument-based silent dedupe, best-effort partial branch, destructive transcript rewrite, detached effectful worker, or implicit replay repair.

## Acceptance tests derived from the evidence

- Equivalent provider responses normalize to stable typed messages/calls; missing and colliding call IDs yield deterministic repair receipts and exactly one settlement per normalized call.
- Identical Bashy arguments execute twice under `allow`, coalesce only under explicit YAML policy and scope, and never authorize a prior effect by accident.
- Sequential barriers preserve order; concurrent calls never exceed declared caps or overlap conflicting resource claims; results remain in call order despite completion order.
- Missing policy evidence, approval transport failure, timeout, restart, changed intent/config/state, or expired consent denies execution.
- A timed-out/cancelled Bashy call is killed or recorded ambiguous and reconciled; it cannot perform an untracked late effect.
- Steering survives restart, is accepted by CAS at a safe point, retains user authority as a typed event, and is never parsed from Bashy output.
- Compression crash before/after candidate, checkpoint, or successor commit leaves one recoverable head and preserves events beyond the source watermark.
- Branch creation is atomic and complete; replay uses the parent watermark without copying partial history.
- Delegate depth/concurrency/aggregate budgets are reserved atomically; parent cancellation/restart fences child launch, completion, join, and delivery.
