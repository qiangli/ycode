# Harness configuration examples

- [`agent.yaml`](agent.yaml) is the complete production-style harness example.
- [`agent-zero.yaml`](agent-zero.yaml) is a lean one-shot baseline. It omits
  context, memory, and session resources; its pipeline has no history-loading
  stage or repeat node. Each request is independent, so it cannot refer to
  earlier turns. Its model has `toolCalls: false`, so a request that needs a
  command such as `pwd` cannot be answered from live workspace state.
- [`agent.schema.json`](agent.schema.json) is the exhaustive structural
  inventory of the supported `ycode.dev/v1alpha1` YAML sections and
  properties. It is generated by `go run ./cmd/ycode schema` and follows the
  YAML tags on the compiler's configuration types. The compiler also checks
  cross-field rules, references, stage contracts, and value constraints that
  JSON Schema cannot express; `ycode validate --file <harness.yaml>` is the
  authoritative validity check.

The JSON Schema describes the document shape. It does not imply that every
section is required: optional resource maps may be omitted when unused.
